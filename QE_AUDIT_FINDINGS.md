## Top 5 fixes for a fast, error-free run

1. **Absolute PQ grayscale targets** (Backend #1) — every HDR ΔE, PQ-error %, and phase-gate decision is wrong by construction today; the golden baseline must be regenerated with it.
2. **ColorTuner delta→absolute ADB write** (Frontend #1) — the only programmatic correction path actively de-calibrates the TV; until fixed, ADB Apply should be considered unsafe.
3. **Limited-range `code_max` in the analyze path** (Backend #2) — stops the LLM loop from "fixing" phantom errors on the most common TV signal path.
4. **HDR luminance ±5%-of-1000-nits gate** (Backend #3) — unblocks every real HDR run; currently a guaranteed dead end on non-1000-nit panels.
5. **Tone-map-knee guard in HDR gamma plans** (Backend #5) — stops perpetual "raise 70/80%" advice that fights firmware tone mapping (explicit ground-truth invariant).

## Needs Evidence (not reported as confirmed)

- **SSE endpoints exhaust the sync threadpool** — `/events/{sid}`, `/api/logs/stream`, `/api/session/{sid}/llm/stream`, `/api/watch/events` are sync generators; each open connection pins one AnyIO threadpool token (default 40) for its lifetime, and one browser tab holds ~3. Evidence needed: a load test showing all sync routes stall at ~13 concurrent tabs. Plausible hang class, no reproduction performed.
- **Round-1 damping (~0.55) invariant is prompt-only** — `calcore/llm.py:1646-1650` implements damping as LLM instructions ("apply a DAMPED fraction (about half)") with no deterministic clamp on returned deltas. Whether the model obeys cannot be verified from the repository; a post-hoc clamp in `predict_next_settings` would make the invariant enforceable.
- **Dead `url` parameter in bridge client calls** — `client.js:93-95` sends `?url=`/body `{url}` that the backend ignores. No user-visible failure found (the UI always saves before checking), but the contract mismatch will bite any future caller that expects to probe an unsaved URL.
